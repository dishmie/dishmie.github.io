SpringIOC

Spring 的 IOC（控制反转）是工厂模式+Java 的反射机制。

  • 出现的原因：在传统的程序开发中，当需要调用对象时，通常由调用者来创建被调用者的实例，即对象是由调用者主动 new 出来的。但在 Spring 框架中创建对象的工作不再由调用者来完成，而是交给 IoC 容器来创建，再推送给调用者，整个流程完成反转，因此是控制反转。
  • 工厂模式：是 Java 中最常用的设计模式之一。这种类型的设计模式属于创建型模式，它提供了一种创建对象的最佳方式。
  • 使用场景：在我们明确地计划不同条件下创建不同实例时使用，而且通常情况下，客户代码不知道或不需要知道创建的对象是来自哪一个类（由服务提供者决定）。 主要解决接口选择的问题。在 Spring 中，是在 spring.xml 中配置 bean 标签，IoC 容器通过加载 bean 标签来创建对象的。spring 中的 bean 都是通过反射的方式生成的， 同时其中包含了很多的扩展点，比如最常用的对BeanFactory 的扩展，对 bean 的扩展（对占位符的处理）除此之外， ioc中最核心的也就是填充具体 bean 的属性，和生命周期

创建流程

  1. 实例化 bean ：反射的方式生成对象
  2. 填充 bean 的属性： populateBean(), 循环依赖的问题（三级缓存）
  3. 调用 aware 接口相关的方法： invokeAwareMethod( 完成 BeanName,BeanFactory,BeanClassLoader 对象的属性设置）
  4. 调用 BeanPostProcessor 中的前置处理方法：使用比较多的有 (ApplicationContextPostProcessor, 设置ApplicationContext,Environment,ResourceLoader,EmbeddVaIueResolver 等对象）
  5. 调用 initmethod 方法： invokelnitmethod(), 判断是否实现了 initializingBean 接口，如果有，调用 afterPropertiesSet 方法，没有就不调用
  6. 调用 BeanPostProcessor 的后置处理方法： spring 的 aop 就是在此处实现的
  7. 获取到完整的对象，可以通过 getBean 的方式来进行对象的获取
  8. 销毁流程。

AOP

bean 的创建过程中有一个步骤可以对 bean 进行扩展实现， aop 本身就是一个扩展功能，所以在 BeanPostProcessor 的后置处理方法中来进行实现

  1. 代理对象的创建过程 (advice, 切面，切点）
  2. 通过 jdk 或者 cglib 的方式来生成代理对象
  3. 在执行方法调用的时候，会调用到生成的字节码文件中找
  4. 根据之前定义好的通知来生成拦截器链
  5. 从拦截器链中依次获取每一个通知开始进行执行，

注入方式

属性注入

设值/字段/属性 注入（Field Injection）；

  • 实现简单、使用简单
  • 功能性问题：无法注入一个不可变的对象（final 修饰的对象）；
  • 通用性问题：只能适应于 IoC 容器；不方便移植到非IoC框架，通用性差
  • 空指针 实例化在依赖注入之前

设计原则问题：更容易违背单一设计原则。

Setter 注入

（Setter Injection）；

  • 符合单一职责的设计原则
  • 不能注入不可变对象（final 修饰的对象）；
  • 注入的对象可被修改。

构造方法注入

（Constructor Injection） 可注入不可变对象； 注入对象不会被修改； 注入对象会被完全初始化； 通用性更好。

循环依赖

原型 bean 不支持，讨论单例 bean 的情况

构造注入

避免栈溢出。那么我们就需要检测是否存在循环依赖的况，如果有就直抛异常 @Lazy 打破环的简单办法是让 Spring 对 bean 进行懒惰的初始化 不要完全初始化 bean，而是创建一个代理来将它注入到其他 bean 中。被注入的 bean 仅仅在第一次被使用时才会完全初始化

三级缓存

解决属性注入

  1. 一级缓存 单例池，singletonObjects (ConcurrentHashMap<String(beanName),Object创建好的单例bean对象>）
  2. 二级缓存 earlySingletonObjects (ConcurrentHashMap<String(beanName),Object尚未完全创建好的单例bean对象>) 如果该 bean 需要进行 AOP ，则该半成品对象就是它的代理对象，否则就是它 实例化 之后但是尚未属性填充的 原始对象
  3. 三级缓存 singletonFactories (HashMap<String(beanName),ObjectFactory尚未创建好的单例 bean 对象的生成工厂>) ObjectFactory:Spring 提供的函数式接口，可以使用 Lambda 表达式实现，可以在任何我们需要结果的时候才真正去执行 bean 实例化后，判断允许循环依赖（默认t），基于当前 bean 的原始对象暴露一个 Lambda 表达式，放入三级缓存 bean 存在循环依赖，取出 Lambda 并执行，返回的对象放入二级缓存 else Lambda 不会被用到，当前 bean 按照自己的生命周期 正常执行，创建完成后放入单例池中 Lambda: 如需进行 AOP ，提前进行 AOP 并返回一个当前 bean 原始对象的代理对象 else 返回当前 bean 的原始对象
